# Changelog: immiscible (the CLI)

## 0.3.0 (not yet published)

Added

- `immiscible attest [--base <ref>] [--comment] [--sign] [--out <file>]`: what the coding agents did on the branch checked out here, as an in-toto Statement about its head (predicate `https://immiscible.ai/attestation/coding-agents/v1`): sessions, models and cost per agent, the guard's decisions by rule, agents that ran with no guard, team rules and whether each day of the decision log verifies. Counts and names only. `--comment` posts it on the pull request with gh and updates the same comment after; `--sign` has the workspace sign it (`POST /v1/cli/attest`), and `verify` checks such a token offline. `attest --check [--strict]` verifies the pull request's attestation in CI (the Action's `attestation` input): exit 11 for an unguarded agent or a broken log, 12 for a signature that does not hold.
- `--help` now opens on coding agents ("what your coding agents did, a guard in front of them in one command, and what any agent may spend, share and do"), with `scan`, `guard`, `undo`, `replay` and `cost` first.
- `guard --status`, `guard --pause <time>` (up to 2h: what would be asked goes ahead, logged as paused; refusals and the asks about agent configuration, the guard's records and secrets stay) and `guard --resume`. The guard now refuses an agent switching itself off, pausing it or pointing it at another server, however the command is spelt (through a variable, `xargs`, quotes, `node $(which immiscible)` or a `.cmd`), asks before any call touches its own records under `~/.immiscible/`, and treats a PowerShell tool like a shell. The CLI also refuses `--off`, `--pause` and `--connect` when it runs inside an agent's shell (exit 6, `agent_shell`). A pause file is honoured only when it is written by `guard --pause` (no start time in the future, two hours at most); a managed guard reads its pause only from the system folder, so `--pause --scope managed` needs an administrator. Team rules are never softened by a pause.
- `immiscible guard --team [--scope managed]`: the workspace's own rules for coding agents (commands to refuse or ask about, protected branches, blocked domains), fetched signed, checked against the server's published keys and the workspace, written to `~/.immiscible/team-rules.json` (or `/etc/immiscible/team-rules.json`) and decided by the local hooks with nothing sent. Team rules only add to the built-in ones. `scan --share` refreshes them and reports the version; `guard --off` removes them. Needs a server with `/v1/cli/coding-policy`.
- `scan --ci` names four risks on each entry: an unpinned package runner (`npx`, `bunx`, `pnpm dlx`, `yarn dlx`, `uvx`, `pipx run` with no fixed version, or `@latest`), a key in the configuration itself (never printed), a `SessionStart` hook that reaches the network, and a remote MCP server over plain http. Shown and annotated as warnings; `--strict` fails the build on them. Risks are reported to the workspace and shown on the Agents page.
- `scan` no longer counts a call as run when the guard refused it or the person declined it: Claude Code writes both to its transcript before the decision, and they are now matched against the guard's log and Claude Code's own "doesn't want to proceed" result. Cursor and Factory Droid get an after-call hook (`afterShellExecution` and `afterMCPExecution`; `PostToolUse`) that never blocks and, in local mode, logs when the person let an asked call run, so `scan` and `replay` tell a yes from a no.
- `immiscible scan --share [--name <name>]`: this machine's guard for the team. Sends agent names, how they are guarded (local rules or the workspace; own or managed settings), decision counts by agent and rule, whether the decision log verifies and the kinds of finding, keyed by a hash of the machine; never a command, path, domain, repository or session. The Agents page lists every machine, and the coverage report counts managed hooks as enforced, own-settings hooks as advisory and an agent with no hook as unseen. Needs a write token and a server with `/v1/cli/guard-report`.
- A token from `IMMISCIBLE_TOKEN` or `--token` is never sent to a server only the project's `.env` names (a cloned repository or a pull request could otherwise choose where it goes): commands that need it stop with exit 3, `token_withheld`, and `doctor` says why. Set `IMMISCIBLE_URL` or `--url` too. A saved sign-in is per server and unaffected.
- A GitHub Action for `scan --ci` (`action.yml` in this package): it runs the CLI from its own checkout, so nothing is installed from npm, and always sets the server address. In GitHub Actions, `scan --ci` also writes the whole list to the job summary, every cell escaped. A CI token is never sent to a server named only in the repository's `.env`, which a pull request can change.
- `immiscible scan` reads the guard's own decision log: a Guard section with what the hooks refused, asked about and allowed, by rule, and a finding when a day of the log does not verify. For Factory Droid, opencode, Amp, Cursor and Windsurf, whose own history scan does not read, the calls their hooks let through are counted like any other agent's (not priced; a refused call never counts as done). The hooks now log the directory each call ran in.
- `immiscible guard --agents all` writes every agent's hook whether or not the agent is installed yet, for a box, dev container or image built before any agent runs; with `--scope managed`, opencode and Amp are left out and named.
- The opencode and Amp hooks send web search and fetch, and any Amp tool that is not a local read, instead of letting them through unchecked.
- `immiscible cost --share` sends each session's agent, repository, branch, pull request, ticket id and cost to your workspace (never a prompt, command or file), and `immiscible cost --team` shows the team's together, per pull request across vendors and people, with `--csv`. Needs a server with `/v1/cli/coding-cost`.
- `immiscible scan --ci [--approve]`: the hooks, plugins and MCP servers a repository configures for any coding agent, each fingerprinted, against the allow list committed at `.immiscible/agent-config.json`; exit 11 on anything not in it, with GitHub Actions annotations. `--approve` writes the allow list for review. Commands and keys are never printed. Signed in, the workspace's allow list counts too and each run is reported to the Agents page (fingerprints and program names only). Needs a server with `/v1/cli/agent-config`.
- `immiscible install droid|opencode|amp`, and `guard` finds them: Factory Droid gets a `PreToolUse` hook in `~/.factory/hooks.json` (or the system `settings.json` with `allowManagedHooksOnly` for `--scope managed`) and asks the person at the keyboard when a person must approve; opencode and Amp, which have plugins rather than command hooks, get a plugin file in `~/.config/opencode/plugins/` or `~/.config/amp/plugins/` that runs the same hook and goes ahead only when it exits 0. Reads are not sent. Neither plugin agent has a managed file: install says what to do instead.
- `immiscible evidence ai-act [--out pack.zip]`: download the EU AI Act deployer evidence pack for the workspace you are signed in to, as a zip with `pack.json` and a readable `SUMMARY.md`, or as JSON when `--out` ends in `.json`. For owners, admins, security admins and auditors. Never replaces a file without `--force`. Exit code 12 when the pack reports that the ledger did not verify. Needs a server with `GET /v1/cli/evidence/ai-act`.
- `immiscible policy replay --file draft.json [--since 30d] [--exclusive]`: what a draft rule would have decided on the requests your agents really made, decided again in order with limits adding up, against what was decided then. Checked, never stored or signed. Needs a server with `POST /v1/cli/policy/replay`.
- `immiscible cost [--by branch|pr|ticket|repo|agent] [--since] [--csv <file>]`: what coding agents cost across vendors together, from the history on the machine at list prices. Two vendors on one branch roll up to one row naming both; sessions with nothing to attribute them to are shown as unattributed, never zero. `--by pr` reads pull requests through `gh` and marks the merged ones; `--by ticket` finds ids like ENG-123 in branch names (and PR titles with `--prs`).
- `immiscible guard` keeps Claude Code's settings honest mid-session: in local mode it also installs `SessionStart` (noting the hooks, broad permission rules, bypass mode and MCP switches the session started with) and `ConfigChange` (matcher `user_settings|project_settings|local_settings`). A settings change during the session that adds a hook, removes Immiscible's, turns hooks off, widens permissions, turns on bypass or adds an MCP server or apiKeyHelper is blocked with a plain reason; anything else goes through. A project hook new to the machine is named once at session start. Hook commands are stored only as a hash and program name.
- `immiscible undo [<checkpoint>] [--dry-run] [--yes]`: undo before approve. Before a call that deletes or overwrites files in a git repository (`rm`, `git clean`, `git reset --hard`, `git checkout --`, `git restore`, `find -delete`, edits to agent configuration) the guard's hooks take a checkpoint under `refs/immiscible/checkpoints/`, never pushed and deleted after 7 days. Claude Code's and Cursor's approval questions name it ("If you approve, it can be undone"), and say plainly when a call cannot be undone. `undo <id>` puts the changed files back byte for byte, removes files made since (never ignored or secret files) and restores the index file itself, so staged work and merge conflicts survive, after taking a checkpoint of the present so it can be undone too. Checkpoints never copy secret files, and linked worktrees keep their own. `IMMISCIBLE_CHECKPOINTS=off` turns checkpoints off.
- `immiscible replay [<session>] [--since] [--html <file>]`: the flight recorder. One timeline per coding-agent session, joining the history Claude Code, Codex and Gemini CLI keep with the decisions the guard's hooks logged: every call in order, the decision and rule on each, refused calls marked as not run. The hooks now write a hash-chained decision log, one file a day in `~/.immiscible/decisions` (`IMMISCIBLE_LOG_DIR`, `IMMISCIBLE_LOCAL_LOG=off`); replay names a removed or edited line and exits 12. Commands are shown with credentials redacted, by known shape and by how random a value looks. Local, no account.
- `immiscible guard`: the fix after `scan`, in one command. Puts one fail-closed hook in front of every coding agent found (Claude Code, Codex, Cursor, Windsurf, Gemini CLI). With no account the hooks decide on the machine from local rules, sending nothing: force pushes to protected branches, `rm -r` of the root or home directory, secrets sent off the machine and disk wipes are refused; publishing, infrastructure changes, `curl | sh`, `sudo`, history rewrites, dropped databases, edits to agent and shell configuration and to Immiscible's own records, and the network after a session read a secret file are asked. A refused force push to a protected branch now says what would do: "Try instead: git push origin main". Decision logs and checkpoint messages redact credentials by shape, by name (`GITHUB_TOKEN=`, `--password`, a URL's `user:pass@`) and by how random a value looks. `--connect --key` sends the same calls to the server for phone approvals; `--off` puts every file back byte for byte; `--dry-run`, `--agents`, `--scope managed`. Both hooks gain `IMMISCIBLE_MODE=local`, with the rules in `scripts/local-policy.mjs`.
- `immiscible scan` finds secrets the agents' own history files hold in plain text (private keys and AWS, GitHub, Slack, npm, Stripe, OpenAI, Anthropic, OpenRouter and Google keys), counted once each and reported by kind and folder only; and counts colleagues at your company's email domain from local git history (`--no-team` to skip). It now ends on `npx immiscible guard`.
- `immiscible scan`: what your coding agents did this week, read from the history Claude Code, Codex and Gemini CLI keep on the machine. Sessions by agent and repository, risky commands (force pushes, `rm -rf`, `terraform apply`, `kubectl`, package publishes), secret files read, domains reached, a secret read followed by the network in one session, cost at list prices, and bypass modes and hooks that are not Immiscible's; it leads with the three most important findings. `--since`, `--json`, `--html <file>`. Runs locally with no account, and never prints or writes prompt text, file contents or secret values. Exit 11 when something is high risk.
- The welcome card: `immiscible` with no command in a terminal, and the new `immiscible about`, show the constellation card: the Cardinal squares drawn in dots (the back square in the dot field's cool family, the front in coral, arriving last), the version, the tagline and the next steps, with the dot field thickening towards the right edge. Compact under 98 columns, plain under 74, plain text on a pipe or in CI, nothing decorative with `--json`. `IMMISCIBLE_CARD=compact` or `classic` to choose; `IMMISCIBLE_NO_MOTION=1` turns off the animation.
- `immiscible install claude-code [--scope user|managed] [--transport command|http] [--key] [--gateway] [--dry-run]`: the Claude Code hook for a whole machine. `user` merges it into `~/.claude/settings.json`; `managed` writes Claude Code's managed settings file (macOS, Linux and Windows paths as Claude Code documents them; `IMMISCIBLE_MANAGED_SETTINGS` names another) with `allowManagedHooksOnly`. The command transport fails closed; the http transport posts `PreToolUse` and `PermissionRequest` to the server's `/v1/hooks/claude-code`. Keeps every other setting and hook, shows the diff first, `--dry-run` writes nothing, and a second run is byte-identical. It runs the copied hook's `--self-test` before changing the settings.
- The bundled hook takes `--self-test`: it builds a sample request, sends nothing, and prints one JSON line (`ok`, the Node version, whether `IMMISCIBLE_AGENT_KEY` is set).
- `immiscible install codex|cursor|windsurf|gemini [--scope user|managed] [--key <key>] [--dry-run]`: a fail-closed hook for each of these coding agents, merged into its own hook configuration (Codex's `hooks.json` or managed `requirements.toml` with `allow_managed_hooks_only`, Cursor's `hooks.json` with `failClosed`, Windsurf's `hooks.json`, Gemini CLI's `settings.json`), keeping everything else and changing nothing when run again. The hook, `hook/coding-agent-hook.mjs` (the repository's `scripts/coding-agent-hook.mjs`), sends the same requests as the Claude Code hook; Codex and Gemini CLI wait for a person to approve, Cursor asks at the keyboard.
- One-line installers, served at `/install.sh` (`curl -fsSL .../install.sh | sh`) and `/install.ps1` (`irm .../install.ps1 | iex`): they check for Node 22.13 or later, install the package globally and show the card.

## 0.2.0 (7 October 2026)

0.1.2 was never published; its changes are in 0.2.0, which adds two commands.

Added

- `immiscible try`: see a governed agent in under a minute, offline and with no account. A made-up finance agent asks the SDK's fake server, started on 127.0.0.1, three times: a tool call is allowed, a payment to a new supplier is held for you to approve at the prompt (`--yes` approves it when there is no terminal), and a payment to a lookalike of a known supplier is denied. It saves the receipt, runs `immiscible verify` on it, says what just happened and ends on `immiscible init`.
- `immiscible verify <receipt> [--keys <file or url>]`: check a signed receipt offline, with the verifier the SDK ships. Without `--keys` the keys come from your server's `/.well-known/immiscible-keys.json` and the receipt must be that server's. Exit code 12 when a receipt is not valid.
- The fake and the verifier are copied from `@immiscible/sdk`'s build into `src/vendor` (`npm run sync`), so the CLI still has no dependencies.

Changed

- The bundled hook says which project each call runs in (Claude Code's `CLAUDE_PROJECT_DIR`, or the working directory), so a coding agent past its intern stage can edit and test inside its project without asking. Anything outside the project still asks a person.
- `doctor` reads `IMMISCIBLE_AGENT_KEY` and `IMMISCIBLE_URL` the way the hook does: the environment first, then `.env`. When the two differ it warns and names which one it checked.
- `doctor` compares the installed hook with the one your server serves at `/downloads/claude-code-hook.mjs`, and warns "the hook is out of date" when they differ, rather than reporting it as fine.
- `check` ends on a next step that matches what it found: `doctor` in a project the hook already governs, `init` only when something is still open.
- `--help` opens on spend and savings: "what your company spends on AI, what it could save, and what your agents may do".
- The package says its next version from the first change after a release, so one version number never names two different codebases; 0.1.1 on npm is the code tagged `cli-v0.1.1`.

Fixed

- `status` counted `init`'s own connection tests in today's figures (a test could show as a refusal). They are left out, as they already were from the agent's record. (A server change.)

## 0.1.1 (6 October 2026)

Added

- `immiscible check`: what the agents on this machine can touch (MCP servers, Claude Code permissions, provider keys in `.env` files and shell config). Runs locally and changes nothing; `--upload` makes a report link from the findings only. Exit code 11 when something is high-risk.
- `immiscible mcp [--client <client>]`: the one-line command or config entry that adds Immiscible's MCP server to Claude Code, Cursor, VS Code, Windsurf, Codex, Gemini or a connector. Changes nothing.
- `help --json`, and `--no-gitignore` for `init`.
- `init --hook` now also adds Claude Code deny rules beside the hook, shown in the same diff: `Bash(rm -rf:*)`, `Bash(rm -fr:*)`, `Bash(sudo rm:*)`, `Bash(git push --force:*)`, `Bash(git push -f:*)`, `Bash(git reset --hard:*)`, `Bash(git clean -f:*)`, `Read(./.env)` and `Read(./.env.*)`. Deny rules you already have are kept, in your order.

Changed

- The hook matcher leaves out Immiscible's own read-only MCP tools, so the hook never asks Immiscible about asking Immiscible. `doctor` accepts the older matcher.
- The bundled hook sends a line break in a Bash command as ` ; `, so two commands never read as one, and marks a command too long to send whole with `[cut]`. Immiscible asks a person about a cut command.
- `doctor` prints the docs link on its own line under each fix.
- The code `init` prints for a tool rule defines the values it uses and opens a ticket rather than sending an invoice, which a tool rule does not cover.

Fixed

- `init` could print an old answer from its test call after a rule changed (for example once a second owner confirmed it). The server now makes the test afresh whenever the agent's rules change.
- An agent made by `init --yes` had no one named as answering for it. The person signing in is now its sponsor, and Something else is recorded as General tasks.
